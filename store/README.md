# Saturn Microsoft Store preparation

This branch prepares a separate MSIX distribution. It is not a certified Store
release. GitHub beta 17 remains unchanged. Store review may require further changes.

## What is ready

- A frozen Windows entry point: bundled Python, Qt and SSH dependencies; no pip
  startup, VBScript launcher or desktop-shortcut script.
- Store channel marker and backend guards against GitHub app updates.
- Store-managed update message in Settings.
- One-folder PyInstaller specification, tile assets, MSIX manifest generator,
  Windows build/smoke test, and GitHub Actions preview workflow.
- Draft listing, privacy policy and reviewer notes under store/submission/.

## Preview build

The Store package preview workflow runs on push to store-preparation. It builds
on Windows; PyInstaller cannot cross-compile a Windows executable from Linux.
The unsigned preview uses a development identity and CANNOT be submitted as-is.
Artifacts include the .msix, checksums and smoke-test logs. A preview must be
signed with a trusted-for-testing certificate before local Add-AppxPackage testing.
No certificate or private key is committed or generated by this workflow.

Locally on Windows with Python 3.12 x64 and Windows SDK installed:

```powershell
./store/build_store.ps1 -Preview
```

## Actual Store identity

In Partner Center reserve the app name, then copy Product identity fields:
Package/Identity/Name, Package/Identity/Publisher and publisher display name.
Use the exact values; they are identifiers, not passwords or private keys.

```powershell
./store/build_store.ps1 -IdentityName '<Partner Center identity>' -Publisher 'CN=<Partner Center publisher>' -PublisherDisplayName '<approved display name>'
```

The Store signs the submitted MSIX after certification. The MakeAppx-built unsigned
package still needs clean-Windows installation and Windows App Certification Kit
testing before submission. Full-trust capability requires explanation in reviewer notes.

## Required Windows validation

- Install/update/uninstall without a separate Python install.
- Launch from Start and Store; check Qt/QML, icon, sound and tray restore/exit.
- Confirm Store update controls never download a GitHub installer.
- Create a server outside the read-only package, accept its upstream EULA and start it.
- Test Java preparation, Bedrock process, local join, SSH TCP tunnel and UDP relay.
- Test two profiles, unique ports, scheduled backup/restart and player controls.
- Check MSIX file/registry virtualization: cache, key storage, known hosts and worlds.
- Confirm uninstall/update behavior and recovery/export of data. Do not promise
  migration from the standalone cache until tested on a real installed MSIX.
- Run WACK and review dependency licenses; resolve every certification issue.

## Submission work requiring the owner

Create/verify the Microsoft developer account; accept Microsoft's developer
agreement personally; reserve the app name; provide the actual package identity;
review privacy/listing text; provide contact/support details and a public privacy
policy URL; complete age-rating and export questions; approve final submission.
The package downloads user-selected third-party server software and runtimes,
which must be disclosed to reviewers. Microsoft determines eligibility.

Sources: Microsoft Learn, "Generating MSIX package components", "Microsoft Store
Policies", and "Code signing options for Windows app developers"; PyInstaller
manual and Qt for Python deployment documentation.
